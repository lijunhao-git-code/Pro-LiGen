# Release scope

Included: all 500 A outputs, all 375 B planned records (including failures), all 150 C branches, retained complete-attempt proposal records, lossless candidate replay inputs, reference molecules and controls, target seeds, receptor review/calibration and 900 docking observations, available docking coordinates/poses, the actual deployed GIN checkpoint and library embeddings, the retrieval library, frozen result-figure inputs, actual saved result figures, and offline numerical/figure reproduction code.

Version v0.2.0 also provides the executable GIN feature functions, graph builder and encoder in `proligen/gin.py`, the retained trainer implementation in `archive/train_gin.py`, and `reproduce/retrieve_references.py`. Reference selection runs entirely from the released checkpoint, molecular library and task records. It can either use the saved library embeddings or encode the full library again. The checkpoint SHA256 remains `b08cf0fa0c2625451711d42336f1c032adc6974933d905e4f526471183182253`.

Not included: raw language-model requests/responses and literature-containing dialogue prefixes, third-party paper text, API credentials/account records, manuscript/illustration source files, unrelated earlier P0/P1 diagnostic runs, or an immutable copy of the externally served language model. The original training split and launch overrides have not been reconstructed by this release; the retained trainer documents the implementation and defaults.

The runnable entry points reproduce statistics, saved-candidate selection, quantitative figures and frozen reference retrieval. The new inference checks do not train a model, generate language-model proposals or execute docking. Historical generation/docking scripts under `archive/` preserve their original server paths and are implementation records rather than the portable entry points listed in README.

`release_manifest.json` identifies release files and hashes. `provenance/copied_file_sources.json` maps copied files to existing local scientific exports using relative paths, with source hashes. Generated CSV mirrors and documentation are separately identifiable. `verification/` contains the checks run for this release. No scientific input value was adjusted to improve a result.
